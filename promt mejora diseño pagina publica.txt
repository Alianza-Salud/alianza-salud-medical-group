Motion & UI Design System
Alianza Salud Medical Group — Injury Management

Objetivo visual: transformar la página pública actual, que ya tiene buena parte de la estructura funcional, en una experiencia moderna, premium, médica y dinámica, sin perder credibilidad ni sobrecargarla.

La regla principal:

La interfaz debe sentirse viva, no animada.

Es decir, el usuario debería percibir movimiento y respuesta, pero no pensar constantemente "ah, eso es una animación".

2. Principio fundamental de Motion

Toda animación debe cumplir al menos una de estas funciones:

1. Orientar

Ayudar al usuario a entender dónde está.

2. Jerarquizar

Indicar qué elemento es más importante.

3. Explicar

Mostrar un proceso o relación.

4. Confirmar

Dar feedback después de una acción.

5. Generar continuidad

Hacer que el scroll se sienta como una historia.

Si una animación no cumple ninguna:

No se implementa.

3. Sistema de duración

Utilizar una escala consistente.

INSTANT
0ms

Para cambios que no necesitan animación.

FAST
120–160ms

Microinteracciones.

NORMAL
200–300ms

Hover, botones, cards.

MEDIUM
400–600ms

Entrada de elementos.

SLOW
700–1000ms

Hero y elementos importantes.

AMBIENT
3000–10000ms

Movimiento ambiental.

4. Easing

No utilizar linear para prácticamente nada excepto movimiento ambiental.

Microinteracciones
cubic-bezier(0.25, 0.1, 0.25, 1)
Entrada de contenido
cubic-bezier(0.22, 1, 0.36, 1)
Elementos que salen
cubic-bezier(0.4, 0, 1, 1)
Movimiento ambiental
ease-in-out

35. Accesibilidad de Motion

Esto es obligatorio.

Detectar:

prefers-reduced-motion: reduce

Si está activado:

eliminar parallax;
eliminar movimiento ambiental;
eliminar scroll storytelling;
reducir transiciones;
mantener cambios instantáneos.

La página debe seguir funcionando perfectamente.

36. Performance

No meter animaciones pesadas porque sí.

Priorizar:

transform
opacity

Evitar animar constantemente:

width
height
top
left
box-shadow

cuando pueda resolverse con transform.

38. Presets de Motion

Por ejemplo:

fadeUp
fadeScale
blurReveal
staggerContainer
staggerItem

slideFromLeft
slideFromRight

Así un componente puede decir:

<Reveal variant="fadeUp">

en lugar de tener animaciones diferentes por toda la aplicación.

39. Tokens de Motion

Incluso puedes definir:

--motion-normal: 280ms

Esto facilita muchísimo el mantenimiento.

41. Sistema de profundidad

No todo debe estar al mismo nivel.

Crear tres niveles:

Level 0

Fondo.

Level 1

Contenido.

Level 2

Cards.

Level 3

CTA / elementos destacados.

Esto se puede conseguir con:

sombras;
blur;
contraste;
background;
borders.

No necesariamente con grandes sombras.

42. Bordes

Evitar:

border-radius: 24px

en absolutamente todo.

Utilizar una jerarquía:

Buttons:       10–12px
Inputs:        10–12px
Cards:         16–20px
Feature card:  24px
Hero visual:   24–32px

Esto genera jerarquía visual.

43. Sombras

No utilizar sombras negras fuertes.

Más bien:

subtle ambient shadow

La sombra debe sugerir profundidad, no parecer que el componente está flotando a 50 cm de la página.

44. Border glow

Para elementos importantes podemos utilizar un glow muy sutil:

border
+
radial highlight

Especialmente:

CTA;
Hero visual;
Injury Management process.

47. Lo que NO implementaría

Para evitar que Gemini/Codex se emocione demasiado:

❌ Lottie en cada sección
❌ Three.js
❌ WebGL
❌ Videos pesados como fondo
❌ Cursor gigante personalizado
❌ Texto que se deforma
❌ Scroll horizontal innecesario
❌ Parallax agresivo
❌ 3D médico falso
❌ Animaciones infinitas en todos los elementos
❌ hover:scale-110 en absolutamente todo
❌ Gradientes chillones

El objetivo no es demostrar que sabemos animar.

El objetivo es que el usuario diga:

"Esta página se siente muy bien hecha."

Para este proyecto, Motion/Framer Motion + CSS + Intersection Observer me parece el punto de equilibrio ideal; solo introduciría GSAP si al implementar el timeline/sticky storytelling descubrimos que realmente necesitamos una sincronización de scroll más avanzada.
